# Social preview：部署與驗收

## 部署

Cloudflare 設定不變：Build `npm run build`，Output `dist`。本次沒有更動 WebSocket relay、Origin、Worker 路由或 CSP；無需新增環境變數，也不要把 BC 帳密加入 Cloudflare 設定。

先 `npm install`、`npm run build`、`npm test`，提交本次修改與新檔後 push。待 Cloudflare 部署完成，重新整理；頁尾應顯示 `Social preview`，手機登入後應看到「房間／聊天／好友／設定」。本次未替你 commit、push 或部署。

## 建議逐項測試

請由你自己登入；不用提供帳密給開發者。多人互見測試要用兩個不同帳號，同帳號登入會互踢。

1. **既有連線回歸**：登入顯示 PROD。女性／男性／混合區各搜尋一次。依完整房名搜尋隱藏房間，確認與原本一致。
2. **建房**：用不重複名稱建立隱藏測試房，選 CN、5 人、自訂描述。確認同步的房名、人數限制及描述。離開後測直接加入。
3. **手機聊天**：持續輸入中文但不要送出，請另一帳號傳訊與進出房間。草稿、中文選字不得消失；只收到聊天時輸入框不會重建。測一般聊天、`/me`、`/w 編號 內容`、Shift+Enter 換行。
4. **紀錄與滾動**：上捲閱讀時接收幾則訊息，不應跳到底部；應出現「新訊息 ↓」。點擊回最新。預設最多顯示 100 則，更多紀錄每次加 100，最多 600；這是記憶體紀錄，不是伺服器歷史。
5. **手機成員**：點「成員」，再點一位玩家；查看個人描述，選房內密語／加好友／BEEP。保留中的草稿被密語指令取代前應有確認。切到好友／設定不應離開房間。
6. **好友**：點重新查詢，與完整版好友列表比對。查不到在線不等於離線：環境、互加、隱私等可能影響查詢。用已知編號加好友，重新登入核對；移除要先確認，再重新登入核對。清單不會背景輪詢，狀態以最後查詢時間為準。
7. **BEEP**：和另一帳號在不同房間互傳文字，分別用 BC 原生及 FCM 測試；對方應收到一份一般文字。輸入 BEEP 草稿時接收訊息，草稿不得消失。附件／人物分享、FCM 控制封包不顯示，未支援離線投遞、通知推播、已讀與送達確認。送出 BEEP 不附帶自己的房間位置。
8. **斷線**：網路切離線再恢復，觀察重連。離線傳送不得清掉草稿或在重連後偷偷補送。登入恢復後重新查好友、重新進房；目前不自動重進房。
9. **顯示負擔**：設定開／關背景。開啟只新增單張約 184 KB JPG，無影片、輪播或角色繪圖。聊天 JS 約 81 KB（gzip 約 26 KB），CSS 約 14 KB（gzip 約 4 KB）；測試用 happy-dom 不在正式 bundle。背景關閉後不再使用圖片；瀏覽器可能仍快取先前下載內容。
10. **隱私**：登出／重新整理後 BEEP 和聊天紀錄消失，密碼不由 Lite 保存。Application → Local Storage 預設只看到 `bc-lite-display-v1` 顯示偏好；自願啟用記住帳號後另有 `bc-lite-account-v1` 帳號名稱。取消勾選或設定頁刪除後確認 key 消失。完整機制與風險見 [privacy-and-appearance.md](privacy-and-appearance.md)；不要把含帳密、完整封包或私人訊息的截圖公開。

## ECHO：實際範圍，不能當成完整版

目前沒有執行 ECHO 主插件或發送假版本標籤。ECHO 的 `src/main.js` 依賴 BC AssetManager、人物與繪圖核心；直接載入不是純文字 Lite 可安全滿足的依賴。

Lite **不會清洗未知服裝欄位、不送 Appearance 或 OnlineSharedSettings 更新**。保留登入時伺服器已存的原始服裝，不等於已實作 ECHO 的換裝／道具操作／雙向同步。好友變更只更新 FriendList。服裝數量是登入快照，不是後續同步狀態。

驗收方式：

1. 在完整版 BC + ECHO 穿好測試服裝並儲存。讓另一位裝有同版 ECHO 的玩家確認外觀。
2. 切到 Lite，用同一帳號進同房；觀看者確認原版衣服、自訂槽位、顏色、疊層。不要在這階段替 Lite 玩家換裝。
3. 在 Lite 加好友或收發 BEEP 後再觀察；最後返回完整版，確認服裝未被 Lite 覆蓋。
4. 若缺衣服，回報「Lite 一進房就缺／觀看者重進房才缺／返回完整版也缺」、ECHO 版本及物品名稱；不需要密碼或整份帳號設定。

觀看者未裝 ECHO 時，擴充服裝本來就不會顯示。完整 ECHO 適配需另行完成資產協定、道具更新與儲存安全性；本輪不假裝已完成這部分。

## 自動測試範圍

Socket／relay 使用模擬事件，不會登入真實 BC 帳號；DOM 測試使用 happy-dom，驗證輸入框身份、草稿、IME、顯示上限、翻讀凍結、BEEP 控制封包與 HTML 不執行。這些測試不能替代真手機鍵盤、視覺排版、BC 多人互見及 ECHO 實測。
