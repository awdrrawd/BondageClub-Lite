# 聊天版面、通知與效能驗收

## 本輪調整

- 互動入口只保留 SVG 部位格子與標籤，移除人物輪廓和下方部位列表；桌機顯示部位＋3／4欄動作。760px 以下分成部位頁、動作頁，可返回部位。缺少原生 Zone 的擴展部位放在旁邊的輔助格。
- 私聊採桌機左側分類／人員、右側對話；手機合併為清單／對話切換，返回按鈕不清除草稿。
- 原生 ServerEnter／Leave／Disconnect／Ban／Kick 通知置中，不另附作者前綴或回覆按鈕；成員同步只更新名單，不再自產第二則進出通知。離房角色暫存在最多 100 人的記憶體快取，換房／登出清除，供延後抵達的通知讀取名字。
- BC LabelColor 直接來自角色共享封包。只接受六位 hex 色；暗色混入白色直到對 #30213a 對比達 4.5:1，缺值則依 ID 使用固定配色。不寫回遊戲。
- 清除只清本機公開聊天室紀錄；不發送刪除封包、不清私聊，不清正在輸入的草稿。
- 回覆預覽移入 InputChat 所在表單上方；有原生 ReplyId 的引用可點回原訊息。已超出本機保存範圍、已清除或不屬於該私聊通道的引用不顯示內容。沒有原生訊息 ID 的回覆仍以純文字引用送出，不能讓接收端憑文字反查原訊息。

## 效能判斷

聊天室預設最多保存 3000 則，預設渲染最後 100 則。設定頁「減壓設定」可選保存 600／1500／3000 則，每批顯示 50／100／200 則。「更多紀錄」切到較早一批，不逐次累積 DOM；回覆跳轉只載入包含原文的那一批，可用新訊息按鈕回最新處。私聊仍預設 60 則，悄悄話跳轉最多 300；不是完整捲動虛擬列表。

`bc-lite-performance-v1` 只保存數量偏好，紀錄仍在分頁記憶體，換房／登出不保留。降低保存上限若會丟棄現有資料需先確認，截斷後無法復原；提高上限也不會重新下載已丟棄的訊息。

公開訊息使用 ID 比對增量添加；私聊本轮也改成 ID 比對，保留舊節點與已載入媒體。一般公開訊息不再連帶重建聯絡人清單。翻閱公開舊紀錄時暫停更新可見切片，避免捲軸跳動。

同一帳戶、連線階段與房名不變時，伺服器同步只更新對應區域：成員按會員編號更新、房間資訊原地修改、搜尋結果與好友卡片保留未變的節點。角色外觀／道具同步、好友查詢回覆、伺服器人數及每分鐘歷史維護不重建整個畫面。訊息修正僅替換有改動的列，聊天翻頁保留重疊列並維持順序；成員抽屜、公開訊息回覆及取消回覆也不替換輸入框。

整頁重建仍用於首次掛載、帳戶／連線階段／房間切換，以及使用者主動切換頁面、對話、語言或部分顯示設定。這是目前的更新邊界，並非所有互動都已改成局部更新。中文組字期間延後結構切換，普通同房同步可直接局部更新。

目前不導入 VDOM：它解決更新差異計算，並非自動減少長列表、媒體解碼或版面繪製。React 同樣先計算差異，再提交必要 DOM 修改，參考 [React Render and Commit](https://react.dev/learn/render-and-commit)。若實機測量顯示每批訊息、尤其圖片／影片時仍慢，下一步應優先考慮可變高度虛擬列表和媒體生命週期；不能僅用 DOM 模擬測試承諾不卡頓。

## 手動測試

1. 桌機寬度與手機 360／390px：互動只見格子；手機點部位後不應同時看到部位與動作。返回、Esc／X、Tab／Enter 均可操作。
2. 私聊切換房間／好友／最近聊天、開啟對象、返回清單。切換對象保留各自草稿；新私訊抵達不重新載入舊圖片或搶走輸入焦點。
3. 兩個測試帳號交替進房、離房、斷線，只看到一則置中通知；暱稱與名稱不同時顯示「暱稱 [名稱]」。重複的網路業務封包本身不在這次去重範圍。
4. 使用亮黃、黑色、深紫色 LabelColor，核對訊息作者與成員名稱清楚可讀。長按訊息仍可複製；懸停／點選訊息可見框線。
5. 回覆後在 InputChat 上方看到預覽；收到帶 ReplyId 的訊息，點引用可跳到舊紀錄並亮起。公開引用不能讀出悄悄話內容。
6. 閱讀舊紀錄時清除訊息，畫面應立即清空；輸入草稿與私聊保留。清除後舊引用顯示不可用。
7. 同房另一人反覆變更外觀、進出或修改房間描述；同時保持中文組字、文字圈選及已開啟媒體。輸入框和未變的訊息列應保持同一 DOM 節點，只有成員／房間欄位更新。靜置超過一分鐘也不應整頁重建。
8. 在搜尋欄或私訊框輸入草稿，再更新搜尋結果／好友在線狀態。草稿、焦點及未變動卡片應保留；私訊對象離房時停用悄悄話並切回 BEEP。

自動測試使用模擬 Socket 與 happy-dom；未取代手機觸控、實際版面和遊戲端驗收。
