# 動作篩選、自動搜尋與連線恢復

## 本輪變更

- 物品判定兼容線上 `{ Group, Name, Property }` 與完整 `{ Asset, Property }`，不修改收到的外觀物件。Effect／活動 Block 採 Asset 與 Property 合併；衣物 Expose／Block 與 AllowActivity 採 Property 優先。未知資料只略過該部分，不再將整體 inventory 標成失敗。靜態物品表新增 Expose、AllowActivity。
- 新增 ZoneNaked／TargetZoneNaked、項圈與 Needs／TargetNeeds 的物品檢查；找不到已知需求物品時拒絕，未知插件規則不假裝已完整驗證。道具專用活動封包、個別插件動態條件仍非完整移植。

- `build-native-activities.mjs` 從本機原生 Female3DCG 資料擷取物品 Effect、Block、AllowActivityOn；只保存靜態條件，不載入圖片、不執行第三方腳本。使用 `node scripts/build-native-activities.mjs` 更新，正常部署不需要原生 BC 倉庫。
- `native.ts` 合併雙方物品與 Property 效果。同次選單列舉共用一次外觀解析；角色／房間更新時刷新面板，發送時再次判定。已知限制不被相容模式略過；尚未實作条件及不完整偏好資料在相容模式改為警告，嚴格模式仍停用。自動興奮／表情效果未模擬只作提示，不再當成任何模式下的使用禁令。
- `extension-rules.json` 保存 ECHO 的靜態前置條件，`build-extension-data.mjs` 將條件併入動作資料，不再只有翻譯。更新上游時執行 `node scripts/build-extension-rules.mjs`；正式建置只讀本倉庫 JSON，不載入插件。貓爪、尾巴、翅膀及觸手的已知穿戴条件區分自己與目標；未移植的插件条件仍有相容模式警告。
- 回歸情境：雙方都沒貓爪時，兩模式下 `猫爪梳毛` 和 `捏猫爪` 皆拒絕；自己戴 PawMittens 後前者可用，只有對方戴 ElbowLengthMittens 時後者可用。普通 Pet／Whisper 在自動興奮模式不因此停用。
- 支援口部阻塞、說話／舌頭、手指／手臂、行走、固定頭部、部分目標口部條件、肛門填塞、封閉與部位 Block／AllowActivityOn。已知不允許的選項不顯示；未知資料或未支援條件仍顯示禁用原因。
- **不是完整 ActivityAllowedForGroup 移植。** 需求道具展開、關係條件與動態插件前置條件尚未完整實作，相容模式只能警告，不能宣稱通過完整檢查；地圖房仍停用。一般擴展文字動作只套用共同外觀／部位檢查，不能宣稱還原各插件私有規則。
- 登入後自動取得所選區域列表；切換區域清除關鍵字並自動查詢，切換語言也查詢。仍遵守滿房、語言等既有選項；隱藏房間仍需正確名稱。DOM 保留分批呈現，不一次插入全部卡片。
- 搜尋請求序列化，快速換區只保留最後一次待查詢条件，丟棄前一區的回覆。BC 回覆沒有請求 ID：逾時後若有待查詢或使用者重試，會重新連線、認證後搜尋，避免舊回覆被當成新結果。這可能短暫離房，沿用既有回房流程。沒有新查詢意圖時不因單次搜尋逾時反覆重連。
- 前景探測接受任意正常的已認證伺服器事件，不再只依賴好友查詢；斷線加入漏訊息提示。不自動補傳聊天、不宣稱送達或已讀。

## 實測

1. 登入後不用按搜尋即可看到目前區域房間；在回原房的登入流程也測一次。切女性、男性、混合；快速連切，最後只能顯示最後選定區域。
2. 搜尋特定名字後切區，關鍵字應清空。語言、滿房等選項仍作用；隱藏房不應因自動查詢公開。
3. 雙方無束縛與一般原生服裝，測耳語、手部活動；再戴口塞、綁手、加行動限制，已知不允許動作不出現，直接發送入口也拒絕。
4. 對方物品 Property.Block 指定部位時，相關 ZoneAccessible 活動受限；AllowActivityOn 開放時依原生規則允許。互動面板開著時更換裝備，點原按鈕也必須重新檢查。
5. 測試未知插件衣物：不可令無關活動停用，兩種模式皆略過無法判定的物品資料；物品附帶的已知效果仍應生效。再加入口塞、封閉、禁止偏好或 Arousal 禁止房間，兩種模式都必須阻擋。一般姿勢不可令所有動作停用，跪姿僅影響相關前置條件。
6. 回前景時延遲好友查詢、但讓聊天繼續進來，不應重新登入。真正斷線應提示可能漏訊息，回房不重送舊訊息。

自動測試是模擬 Socket 與 DOM；仍需手機及雙人實測。UI 外觀未重設計。送達狀態、媒體併發／釋放、翻譯載入拆分與更完整插件判定仍未完成。
