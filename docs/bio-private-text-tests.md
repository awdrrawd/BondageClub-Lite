# BIO、好友私訊與互動文字驗收

1. 開啟一位有長中文 BIO 的玩家資料，BIO 預設收合，展開後應顯示解壓文字，保留換行。原本沒有壓縮的 BIO 也能顯示。HTML／腳本字串只能顯示為文字。Lite 不會修改或上傳 Description。
2. 同房好友列選「私訊（密語）」：對象預填，輸入內容送出後，只有雙方收到 Whisper，私訊區顯示本房間與該對象的密語。對方离房後不得自動改發 BEEP，應保留草稿並提示。
3. 跨房好友選 BEEP，或私訊方式選 BEEP：使用 BC AccountBeep。這不是同房 Whisper；沒有離線投遞或送達回條。
4. 對 A 輸入草稿，點 B，再回 A：兩人的草稿不可混用。登出會清除草稿；不寫入 localStorage。聊天室主輸入框與好友私訊輸入框仍各有自己的草稿。
5. 讓另一位玩家做舔耳等互動，`ChatOther-ItemEars-Lick` 應顯示帶雙方名字的中文句子。測試舊格式 `{Tag, MemberNumber}` 與新格式 `{SourceCharacter}`／`{TargetCharacter}` 的替換已有自動測試。
6. 玩家直接聊天輸入 `ChatOther-ItemEars-Lick` 時不可被翻譯；只有 Action／Activity／ServerMessage 走文字表。Status（例如 Talk、null、Wardrobe）為角色狀態封包，不進入聊天紀錄或觸發未讀；玩家真的聊天輸入 Talk／null 仍保留。未知插件鍵名保留原文，避免偽造含义。
7. 首次登入後 Network 只多載入所選語言的一份文字 chunk：中文約 148 KB gzip、英文約 130 KB gzip，無圖片或外部翻譯服務。切換語言才載入另一份。文字表晚到時，本次尚留在記憶體的互動訊息會補翻譯；請再測一次手機閱讀位置。載入失敗可重新整理或切換語言重試。

資料優先使用 BC TW 翻譯，不足時使用 CN，再不足保留英文。不是完整 BC 的資產特例／代名詞引擎，也未載入 ECHO 活動翻譯；這些仍可能不完整。原始事件與代入資料只在最多 600 則的聊天記憶體內保留。

建置會對各約 820 KB（未壓縮）的獨立文字 chunk 提示超過 500 KB；這不是建置失敗。每種語言刻意維持單一延遲載入請求，避免拆成大量小檔案。
