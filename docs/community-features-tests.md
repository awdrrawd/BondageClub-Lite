# 社群動作、私聊與媒體授權驗收

本輪以模擬 Socket.IO 與 DOM 自動測試驗證，尚未使用真實帳號或手機驗收。部署設定不變；提交並推送後，等 Cloudflare 建置成功再測試。不要公開帳密、私人對話或完整封包。

## 支援範圍

- 不安裝或執行小酥、LSCG、ECHO 活動插件。只讀取封包內的原文替代文字，以及靜態擷取的 407 條動作模板／語言；中文沒有對應翻譯時保留英文／原文。动态生成、未附文字或未收錄的動作不保證可辨識。資料來源及授權見 [third-party-dialogues.md](third-party-dialogues.md)。
- AFC 擴展戀人來自公開共享欄位；只向自己的 AFC 戀人且在好友名單內的人查詢房間，並只接受自己的 AFC 戀人回覆。對方必須在線、啟用相應 AFC 功能並允許分享；查不到不代表沒有戀人。Lite 不回傳自己的房間，也不改寫 AFC 設定。
- BCX 召喚是接收相容的普通 BEEP，使用 Lite 本次登入的允許名單與關鍵字，收到後由自己確認加入。**沒有讀取 BCX 私有規則狀態、強制倒數或自動跟隨**。隱藏控制訊息不執行。
- 個人資料的互動目前是揮手、點頭、微笑、擁抱等文字 Action。**不是原生 ActivityRun，也不執行束縛、身體效果、插件專屬判定或換裝**。
- 回覆有原生 MsgId 時送 ReplyId；否則以文字引用。BEEP 使用文字引用，不宣稱與 FCM 原生回覆串、附件或離線訊息相容。

## 部署後手動測試

1. 找可信任的同房玩家，分別用小酥、LSCG、ECHO 執行一個對人／自身動作。Lite 應顯示可讀句子；切換中英文後確認仍能辨識。檢查含物品、部位、玩家名稱及插件內嵌文字的消息；隱藏控制訊息不應出現在聊天。
2. 分別開啟沒有主人／戀人、有原生關係、有 AFC 關係的個人資料。應顯示有／無或具體姓名，而不是「未提供」。從自己的 AFC 清單查詢房間；對方關閉分享或離線時不得沿用成已確認在线房名。
3. 在聊天發送 HTTPS 圖片與影片直連。第一次只顯示連結及許可按鈕，瀏覽器 Network 不應出現該媒體請求。「本次許可」允許同來源媒體，重新整理／登出後失效；「總是許可」重整仍保留。設定頁撤銷後，同來源媒體回到許可提示。注意：撤銷不能收回已送出的請求，且已允許來源的 HTTP 重新導向仍由瀏覽器處理。
4. 用手機窄螢幕確認頂欄依序是 Lite、玩家、安全詞，右側語言／登出；聊天室選單不再有第二個安全詞。點成員面板外側關閉，輸入框草稿不能消失。
5. 私聊頁切換房間／好友／最近聊天。對同房玩家發悄悄話，跨房用 BEEP；好友頁不再放完整私訊編輯區。切換對象確認草稿分開，離房後最近悄悄話仍保留於本次登入記憶體；登出清除。
6. 回覆公開聊天、悄悄話及 BEEP。收件人與通道必須正確；公開聊天絕不可帶出私人回覆內容。切換通道／取消／送出後，回覆提示應清除。BC 原生客戶端有 MsgId 的消息需核對 ReplyId 是否正常呈現。
7. 發送 `*揮手*`、`(暫離一下)`、`.a 點頭`、`.A 點頭`、`/w 編號 你好`。分別確認 emote、OOC 普通聊天、Action 及悄悄話，不應顯示控制鍵或 null 雜訊。
8. 設定頁啟用召喚、填入可信任會員編號與關鍵字，按套用。該玩家從另一房間發符合文字的普通 BEEP，Lite 應顯示加入確認；未點接受前不得離房。未允許玩家、不符文字、無房名、插件控制型 BEEP 都不得召喚。關閉規則或等待 60 秒後，舊邀請不得加入。登出後規則預設關閉。
9. 個人資料的文字互動由同房玩家觀察，確認句子及對象正確，沒有外觀改寫或虛假的遊戲效果。目標已離房或自己斷線時應拒絕。

媒體請求會向來源透露 IP 等連線資訊；允許網域不代表掃描或安全認證。請先用可刪除的測試文字與可信任來源驗收。
